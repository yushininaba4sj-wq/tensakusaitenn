# 画像アップロード設定（友達＝管理者向け）

GOUKAKU LINK から送られた**答案・問題の画像**を、SENPAI LINK と同じ管理者画面（`student_service_requests`）で見られるようにするための設定です。

## やること（Supabase SQL Editor）

**① 既に `goukakulink_submissions` がある場合**

```sql
-- supabase/migrations/20260610_add_image_urls.sql の内容
alter table public.goukakulink_submissions
  add column if not exists image_urls text[] not null default '{}';
```

**② Storage RLS（必須・Bucket not found 対策）**

`supabase/storage.sql` をそのまま実行してください。  
手順書: **`supabase/Bucket-not-found-修正.md`**

- バケット名: **`service-request-attachments`**（SENPAI LINK 側の既存バケット。新規作成しない）
- ログインユーザーは自分のフォルダ（`{user_id}/...`）にだけアップロード可
- 管理者画面側は従来どおり `student_service_requests` を参照

## 仕組み

1. ユーザーが GOUKAKU LINK で画像付き依頼を送る
2. 画像 → Supabase Storage（`service-request-attachments` バケット）
3. 依頼テキスト → `goukakulink_submissions`（マイページ用）
4. **同時に** SENPAI LINK 管理者画面用の `student_service_requests` にも登録
   - `message`: `[GOUKAKU LINK / 添削]` などのヘッダー付き
   - `attachments`: `{ url, bucket: "service-request-attachments", path, ... }`
   - `service_type`: `correction` / `kakomon_bunseki` / `study_room` / `plan`
   - `status`: `new`

## 管理者画面での見え方

SENPAI LINK の既存「サービス依頼」一覧に、**GOUKAKU LINK からの依頼も混ざって表示**されます。  
メッセージ先頭に `[GOUKAKU LINK / …]` が付いているので判別できます。

## 確認チェックリスト

- [ ] `storage.sql`（RLS）実行済み
- [ ] `student_service_requests_rls.sql` 実行済み
- [ ] `image_urls` カラム追加済み
- [ ] GOUKAKU LINK から画像付きでテスト送信
- [ ] 管理者画面の `student_service_requests` に行が増える（status=new）
- [ ] ダッシュボード「GOUKAKU依頼 受付済み」に計上される
- [ ] 添付画像が開ける

## うまくいかないとき

- **Bucket not found** → `service-request-attachments` バケットが SENPAI 側に存在するか確認。RLS は `storage.sql` を実行。
- **RLS policy** エラー → `storage.sql` のポリシーを確認
- 管理者画面に出ない → `student_service_requests` への INSERT 権限（`student_service_requests_rls.sql`）
- 累計には出るが「要対応」に乗らない → `status` が `new` か、`service_type` が正しいか（`kakomon_bunseki` 等）
