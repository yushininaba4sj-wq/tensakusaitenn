# 画像アップロード設定（友達＝管理者向け）

GOUKAKU LINK から送られた**答案・問題の画像**を、SENPAI LINK と同じ管理者画面（`student_service_requests`）で見られるようにするための設定です。

## やること（Supabase SQL Editor）

**① 既に `goukakulink_submissions` がある場合**

```sql
-- supabase/migrations/20260610_add_image_urls.sql の内容
alter table public.goukakulink_submissions
  add column if not exists image_urls text[] not null default '{}';
```

**② Storage バケット作成（必須）**

`supabase/storage.sql` をそのまま実行してください。

- バケット名: `service-attachments`
- ログインユーザーは自分のフォルダにだけアップロード可
- 管理者画面側は従来どおり `student_service_requests` を参照

## 仕組み

1. ユーザーが GOUKAKU LINK で画像付き依頼を送る
2. 画像 → Supabase Storage（`service-attachments` バケット）
3. 依頼テキスト → `goukakulink_submissions`（マイページ用）
4. **同時に** SENPAI LINK 管理者画面用の `student_service_requests` にも登録
   - `message`: `[GOUKAKU LINK / 添削]` などのヘッダー付き
   - `attachments`: 画像 URL の配列
   - `service_type`: `correction` / `kakomon` / `study_room` / `plan`

## 管理者画面での見え方

SENPAI LINK の既存「サービス依頼」一覧に、**GOUKAKU LINK からの依頼も混ざって表示**されます。  
メッセージ先頭に `[GOUKAKU LINK / …]` が付いているので判別できます。

## 確認チェックリスト

- [ ] `storage.sql` 実行済み
- [ ] `image_urls` カラム追加済み
- [ ] GOUKAKU LINK から画像付きでテスト送信
- [ ] 管理者画面の `student_service_requests` に行が増える
- [ ] 添付画像が開ける

## うまくいかないとき

- **Bucket not found** → `storage.sql` 未実行
- **RLS policy** エラー → `storage.sql` のポリシーを確認
- 管理者画面に出ない → `student_service_requests` への INSERT 権限（RLS）を SENPAI LINK 側で確認
