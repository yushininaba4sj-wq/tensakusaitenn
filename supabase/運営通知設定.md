# 運営通知（Slack）設定

GOUKAKU LINK からの添削・質問・過去問依頼が、運営側の Slack に届くようにする設定です。

## 原因（なぜ通知が来なかったか）

| 経路 | SENPAI LINK 本体 | GOUKAKU LINK（修正前） |
|---|---|---|
| 依頼の保存 | `/api/student/service-requests` | Supabase へ直接 INSERT |
| Slack 通知 | API 内で送信 | **なし** |

GOUKAKU LINK は DB には入っていても、**SENPAI LINK の API を通らない**ため Slack 通知が飛びませんでした。

## 修正後の流れ

1. **優先:** SENPAI LINK API（`/api/student/service-requests`）経由 → SENPAI LINK 側と同じ Slack 通知
2. **フォールバック:** API 失敗時は DB 直接 INSERT + GOUKAKU LINK 側 Slack Webhook

## Vercel 環境変数（必須）

Vercel → `tensakusaitenn` project → Settings → Environment Variables

| 変数名 | 値 | 用途 |
|---|---|---|
| `OPS_SLACK_WEBHOOK_URL` | SENPAI LINK と同じ Slack Incoming Webhook URL | API 失敗時の通知 |
| `SENPAI_LINK_ORIGIN` | `https://senpailink.vercel.app` | 省略可（デフォルト値あり） |

設定後、**Redeploy** してください。

## 確認手順

1. GOUKAKU LINK にログイン
2. 添削 or 質問 or 過去問フォームからテスト送信
3. 以下を確認:
   - 画面が「送信しました」になる
   - SENPAI LINK 管理画面に `[GOUKAKU LINK / …]` の行が増える
   - **Slack に新規依頼通知が届く**

## うまくいかないとき

| 症状 | 確認 |
|---|---|
| 「管理者画面への連携に失敗」 | `student_service_requests` への INSERT 権限（RLS）→ **`supabase/student_service_requests_rls.sql` を SQL Editor で実行** |
| 管理画面には出るが Slack が来ない | `OPS_SLACK_WEBHOOK_URL` が Vercel に未設定 |
| 画像アップロード失敗 | `supabase/storage.sql` 未実行、または `service-request-attachments` バケット未確認 |
